# G4 单位经济模型与击穿页数测算

目的：在写产品代码之前算清"最坏档位下还赚不赚钱"，避免用户越多亏越多。

## 0. 数据标签规则（硬性）

| 标签 | 含义 | 能否作为 G4 结论依据 |
|---|---|---|
| `[假设]` | 依据公开信息或经验暂填 | **不能**，必须由真实数据替换 |
| `[真实]` | 来自实际收款、真实账单、真实使用日志 | 可以 |
| `[待填]` | 尚未获得 | 不可以 |

**禁止把 `[假设]` 当结论。** 下面所有数值都带标签；只有全部关键参数变成 `[真实]` 后，G4 才能判 PASS。

## 1. 参数表

| 参数 | 当前值 | 标签 | 来源 / 替换方式 |
|---|---|---|---|
| 订阅价 | $9.9/月 | [假设] | 沿用 CRO-001-C 锚点；用 G2 真实预付金额替换 |
| 买断价 | $19.9/次 | [假设] | 同上 |
| MoR 手续费 | 5% + $0.50/笔 | [假设] | LemonSqueezy / Paddle 公开区间；签约后按真实账单替换 |
| OCR 单价 | $0.006/页 | [真实-市场价] | G3 实测：Apify inkbridge actor 公布 OCR 页单价；自有引擎成本需实测后替换 |
| 文本层 PDF 成本 | $0/页 | [假设] | 本地 pdf.js/docling 抽取；需压测电费与计算成本后替换 |
| 每用户月均页数 | 30 页 | [假设] | 必须用真实使用日志 p50/p90 替换 |
| 退款率 | 5% | [假设] | 用真实 MoR 退款记录替换 |
| Supabase + Upstash 固定成本 | $0/月 | [假设] | 免费额度内；超额按真实账单替换 |

## 2. 计算公式

```
单笔净收入   = 标价 × (1 - MoR 费率) - 每笔固定费
退款摊销     = 标价 × 退款率
可覆盖成本   = 单笔净收入 - 退款摊销
变动成本     = OCR 页数 × OCR 单价 + 超额基础设施分摊
单笔毛利     = 可覆盖成本 - 变动成本
击穿页数     = 可覆盖成本 / OCR 单价      （毛利降到 0 的页数）
```

"击穿页数"是最直观的风控线：**用户月度用量超过它，你就在倒贴钱。**

## 3. 示例计算（仅演示公式，不是结论）

以订阅 $9.9 为例，全部按上表假设：

```
单笔净收入 = 9.9 × 0.95 - 0.50 = $8.905
退款摊销   = 9.9 × 0.05        = $0.495
可覆盖成本 = 8.905 - 0.495     = $8.410
击穿页数   = 8.410 / 0.006     ≈ 1401 页/月
```

买断 $19.9 同理：可覆盖成本 ≈ $17.41，击穿页数 ≈ 2902 页。

对照假设用量 30 页/月，变动成本仅 $0.18，毛利看似很厚——**但这正是假设最危险的地方**：如果真实 p90 是 1500 页/月，订阅用户就会击穿。所以必须用真实日志重算。

## 4. G4 PASS 规则（先冻结，再算）

1. 关键参数（标价、MoR 实费、OCR 实成本、p90 页数、退款率）全部为 `[真实]`；
2. 以 **p90 页数 + 高退款率情形** 计算，单笔毛利仍 > 0；
3. 击穿页数 > p90 页数 × 1.5（留安全边际）。

三条同时成立才 PASS；否则调整定价、限页或更换 OCR 引擎，**不开 MVP**。

## 5. 待填清单（按来源逐项替换）

| 待填项 | 数据来源 | 当前标签 |
|---|---|---|
| 真实成交价与订单数 | G2 预付表（MoR 订单号） | [假设] |
| MoR 实际费率与固定费 | 签约后的 MoR 账单 | [假设] |
| 自有 OCR 每页成本 | 压测 + 云账单 | [真实-市场价] 需替换 |
| p50 / p90 月页数 | 真实使用日志（产品上线后） | [假设] |
| 退款率与退款金额 | MoR 退款记录 | [假设] |
| 基础设施超额费用 | Supabase / Upstash 账单 | [假设] |

> 备注：产品未上线时不可能拿到"真实使用日志"，因此 G4 在 G1/G2 阶段只能做到"用真实成交价与真实成本算出边界条件"；p90 用量必须在灰度期内补齐，不能靠猜。
